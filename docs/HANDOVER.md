# Novus Project Handover Document (인수인계 및 내부 동작 명세)

본 문서는 다른 개발자 또는 AI 어시스턴트가 프로젝트에 투입되었을 때, 지체 없이 **시스템의 내부 기능과 동작 메커니즘을 파악하고 바로 개발을 이어갈 수 있도록** 작성된 실무 명세서입니다.

---

## 1. 프로젝트 요약

- **프로젝트명**: Novus (`com.novus.hub`)
- **목적**: 저사양 태블릿(4GB RAM급 Surface Pro 4 m3)을 위한 초경량 미디어 콘솔 및 TV형 제어 대시보드
- **기술 스택**: Tauri v2 (Rust) + React 19 + TypeScript + Vite 8 + pnpm
- **아키텍처**:
  - 프론트엔드: Modular Layered Architecture (FSD 기반 단방향 계층: `app` -> `pages` -> `widgets` -> `features` -> `entities` -> `shared`)
  - 런타임/엔진: OS 시스템 웹뷰 허브(대시보드) + 싱글톤 브라우저 페이지 매니저(인앱 스트리밍)

---

## 2. 핵심 서브시스템 내부 동작 메커니즘 (How it Works)

### ① 대시보드 허브와 인앱 스트리밍의 분리 구조

- **허브 UI**: OS 시스템 웹뷰(macOS WebKit, Windows Edge WebView2)에서 구동되며 대기 시 **RAM 30MB 안팎**의 초경량 점유율을 유지합니다.
- **인앱 스트리밍 뷰포트**:
  - HTML `<iframe>`을 일절 사용하지 않으며, `Window.add_child()`를 통해 네이티브 자식 뷰로 도킹됩니다.
  - 앱 수명과 동일한 **단일 브라우저 프로세스(싱글톤)** 풀에서 각 스트리밍 URL을 페이지(탭) 단위로 관리합니다.

### ①-1 홈 v2 (`HomeV2Screen` → `HomeV2`)

- **텍스트 선택 없음**: 터치 기기용으로 앱 전체에서 글자 선택, 길게 누르기 메뉴, 이미지 끌기를 막습니다(`app/styles/v2/base.css`, WebKit용 `-webkit-user-select` 포함). 입력칸만 선택·편집할 수 있습니다.
- **홈은 v2 하나뿐입니다.** v1 대시보드(QuickHeader·MediaShelf·구 설정)는 삭제되었습니다. 갤러리·파일·사진 뷰어·독·스트리밍 로딩은 v2 컴포넌트이고, 동영상 플레이어 내부만 v1 구조에 v2 외형을 입혀 `.nv-bridge` 안에서 렌더링합니다.
- **진입 프레임**: 앱을 처음 켜면 1화면(사진)으로 시작합니다. 스트리밍·갤러리·파인더에서 홈/뒤로로 돌아오면 2화면(오늘 한 장)에 바로 놓이고, 60초 동안 입력이 없으면 1화면으로 부드럽게 돌아갑니다(`HomeV2` `entry`, `autoReturnMs`).
- **멀티태스킹 트레이**: 실행 중인 세션이 있으면 1화면 캡션 아래에 "실행 중 N" 칩(로고·이름·닫기)이 나옵니다. 칩을 누르면 복귀, ×는 세션 종료. 2화면 서비스 타일에도 실행 중이면 닫기 버튼이 붙습니다.
- **로고**: 원래 브랜드 로고 `src/assets/novus-logo.png`(NV + novus)를 마스크로 써서 배경에 따라 흰색/잉크색으로 표시합니다(`NovusLogo`). 1화면 왼쪽 위와 2화면 사진 띠에 있습니다.
- **사진 교체**: 다음 사진은 화면 밖에서 `decode()`까지 끝낸 뒤 두 레이어로 크로스페이드합니다. 반쯤 디코딩된 사진이 보이지 않습니다.
- **1화면 (한 화면 한 개)**: 사진 위에 캡션. 실행 중 세션이 있으면 가장 최근 것을 "실행 중 · 세션 유지 · N분 전 사용"과 이어서 보기/다른 세션 열기/세션 종료로 보여줍니다. 실행 중이 없으면 마지막으로 쓴 서비스, 그것도 없으면 시간대 인사만 보여줍니다. 오른쪽 원형 레일은 검색·갤러리·파일·리모컨·설정.
- **2화면 (오늘 한 장)**: 스크롤 스냅으로 내려오면 같은 사진이 위로 접혀 띠(화면 높이의 13%: 로고, 검색·테마·설정, 가운데 위쪽 "사진 ⌃" 힌트)가 됩니다. "사진 ⌃"은 1화면의 "오늘 · 서비스 ⌄"와 같은 모양(판 없이 글자 + 꺽쇠)이며 누르면 사진으로 돌아갑니다. 두 화면 사이는 휠, 이 버튼 클릭·탭, 그리고 **끌어 올리기/내리기**(`useFrameDrag`: 터치·마우스·펜으로 누른 채 위아래로 밀면 사진 접힘이 손가락을 따라오고, 놓으면 화면 높이의 18% 이상 움직였거나 64px 이상 빠르게 튕겼을 때 다음 화면으로, 아니면 제자리로 0.38초 동안 돌아감. 끄는 동안 스크롤 스냅을 멈추고, 끈 뒤에 따라오는 클릭은 무시. 브라우저가 스스로 패닝하지 않도록 `touch-action: none`)로 오갈 수 있고, 2화면 위쪽 사진 띠를 (버튼이 아닌 곳을) 탭해도 사진으로 올라갑니다. 꺽쇠는 2.2초마다 5px씩 움직여 누를 수 있다는 걸 알립니다(동작 줄이기 시 정지). 그 아래는 3줄 그리드입니다. 1줄: 왼쪽 큰 날짜(요일·월·올해 N번째 날) 오른쪽에 큰 시각과 날씨 | 이번 달 달력(Google 캘린더 열기). 2줄(전체 폭): 서비스 16:9 타일 2행. 열 수(4–9)는 `HomeV2`의 ResizeObserver가 1·3줄을 뺀 남은 높이로 계산해 타일을 최대한 크게 유지하고, 서비스 → 모든 앱 → 점선 예약 칸 순으로 2행을 채웁니다(서비스 추가 시 예약 칸에 들어감, 숫자키 1–7). 3줄(전체 폭): 탐색기 줄(갤러리·파일·라디오(앱 단위만, 다운로드·드라이브 같은 위치는 갤러리 위치 메뉴와 파일에서 고름) | 앰비언트·모바일 리모컨 "준비 중"). 모두 박스 없는 텍스트 버튼이며 항목 사이를 얇은 세로선(|)으로 구분합니다. 1280×800–1920×1080에서 한 화면에 들어갑니다.
- **사진 접힘 초점**: 띠는 사진의 초점 높이(`photoFocus`, 번들 아트워크별 `focusY`)를 중심으로 보입니다.
- **사진**: `useAmbientPhoto`가 설정의 사진 폴더(기본은 OS 사진 폴더)에서 최신 40장을 1600px 썸네일로 돌립니다(홈 10분, 앰비언트 1분 간격). 폴더가 없거나 비었거나 읽을 수 없으면 `src/assets/ambient/`의 번들 아트워크.
- **캡션 문법**: 제목이 먼저, 그 아래 상태 줄("● 실행 중 · 12분 전"), 그 아래 맥락 줄. 제목 위에는 아무것도 두지 않습니다. 실행이 끝난 최근 서비스는 "세션이 끝났어요 · 다시 열면 첫 화면부터".
- **태블릿형**: 오른쪽 레일이 화면 아래쪽(엄지 닿는 곳)에 붙습니다. TV형은 세로 가운데.
- **앰비언트**: `useIdle`이 설정한 분(기본 10분) 동안 입력이 없거나 앰비언트 버튼을 누르면 캡션·레일이 사라지고 사진과 오른쪽 아래 큰 시계·날짜만 남습니다(모서리 스크림만). 사진이 없으면 번들 아트워크도 1분마다 바뀝니다. 전체를 덮는 투명 버튼이 첫 터치·키 입력을 받아 깨우기만 하고 아래 요소로 전달하지 않습니다. 스트리밍·오버레이가 열려 있으면 멈춥니다.
- **날씨**: `useWeather`가 설정의 도시로 Open-Meteo를 30분 이상 간격으로 조회합니다(마지막 값 캐시). 도시 미설정·오프라인이면 숨깁니다.
- **세션 종료 표시**: 세션을 닫으면 플레이트가 1.5초 동안 "종료됨"을 보인 뒤 대기 상태로 돌아갑니다.
- **모바일 리모컨**: 서버가 아직 없어 "준비 중" 안내만 띄웁니다.
- **테마 브리지**: v1 화면이 읽는 `html.dark`를 v2 테마 설정(`useResolvedTheme`)에 맞춰 App이 동기화합니다.

### ①-2 첫 실행 온보딩 · 설정 v2

- **온보딩** (`widgets/onboarding`): `onboardingDone`이 false이고 v2 홈일 때 앱 시작 화면으로 나옵니다. 언어 → 보기 모드 → 사진 폴더. 온보딩 자체는 태블릿형 배율로 고정되고, 보기 모드 단계에서는 오른쪽 애니메이션 미리보기(`PosturePreview`)로 차이를 보여줍니다. 실제 Novus 화면의 축소판이 기기 안에서 재생됩니다. TV형은 벽걸이 화면에서 리모컨 오른쪽 키로 포커스가 서비스 줄을 이동하고 OK로 실행 화면이 열리며 방 조명이 서비스 색으로 바뀝니다. 태블릿형은 3:2 기기의 오늘 페이지에서 손끝이 타일을 눌러 실행합니다. 포커스·터치는 타일 자체에 붙어 있어 어긋나지 않고, 화면 단위는 `cqw`라 크기와 무관하게 맞습니다. 1.1초 박자 타이머는 보이는 장면에서만 돌고 동작 줄이기 설정에서는 정지 화면입니다(폴더 선택기, 건너뛰면 OS 사진 폴더). 마지막 단계에서 `onboardingDone=true`.
- **설정 v2** (`widgets/settings-v2`): 오른쪽 시트 하나에 화면·홈·시스템·업데이트·현재 기기 구역. 언어·사진 폴더·날씨 지역은 시트 안 하위 화면(뒤로 버튼)입니다. 스트리밍 화면에서 열 때도 같은 시트를 씁니다(네이티브 웹뷰는 그동안 숨김).
- **날씨 지역 검색**: Open-Meteo 지오코딩을 350ms 대기 후 호출, 2자 이상일 때만. 고른 도시는 `weatherCity`에 저장.
- **부팅 시 자동 시작**: `tauri-plugin-autostart`(Windows 레지스트리 Run 키, macOS LaunchAgent). 프런트는 `shared/api/tauri/autostart.ts`가 `plugin:autostart|*` 커맨드를 호출합니다. 브라우저 DEV에서는 비활성 + "데스크톱 앱에서 사용할 수 있습니다".
- **업데이트 v2 화면** (`UpdateSettingsV2`, `UpdateNoticeV2`): v1과 같은 `updateController`를 쓰고 화면·문구만 v2(다국어)입니다. 컨트롤러가 만드는 오류 문구는 한국어라서, 다른 언어에서는 일반 오류 문구로 대체합니다.
- v1에 있던 "배터리 스웰링 방지 모드" 토글은 동작이 없는 자리표시라 v2에서 뺐습니다.

### ② 스트리밍 페이지 매니저 (`src-tauri/src/page_manager.rs`)

1. **지연 생성 (Lazy Creation)**:
   - 사용자가 스트리밍 카드를 클릭하기 전에는 백그라운드에 페이지를 미리 띄우지 않습니다.
   - 첫 클릭 시점에만 해당 `id`의 자식 뷰를 생성하여 뷰포트 좌표에 도킹합니다.
2. **세션 유지 숨김 (Hide != Destroy)**:
   - 홈 버튼을 누르면 웹뷰를 파괴하지 않고 `hide_streaming_page`를 호출하여 화면 밖으로 숨깁니다.
   - 렌더러 메모리와 로그인 세션 쿠키가 그대로 보존되어 재진입 시 즉시 이전 상태가 복원됩니다.
3. **무중단 동적 레이아웃 및 창 리사이징 (`update_streaming_page_bounds`)**:
   - `ResizeObserver` 및 `window.resize` 리스너를 결합하여, 독 위치 변경 뿐만 아니라 **사용자가 메인 창 크기를 동적으로 조절할 때도 웹뷰 크기가 뷰포트에 맞게 실시간 자동 동기화**됩니다.
4. **지능형 뒤로가기 및 메모리 해제 (`go_back_or_close_streaming_page`)**:
   - 인앱 플레이어 독의 '뒤로가기' 버튼을 누르면 먼저 Chromium 히스토리 뒤로가기(`history.back()`)를 시도합니다.
   - **더 이상 뒤로갈 이전 페이지가 없는 첫 진입 페이지에 도달한 상태에서 뒤로가기를 누르면**, 해당 페이지를 완전히 `discard` 파괴하여 백그라운드 메모리를 즉시 반환하고 대시보드 홈으로 자동 복귀합니다.
5. **User-Agent 정직화 전략**:
   - 구글 안티어뷰즈(`accounts.google.com`) 탐지 방지를 위해 YouTube/Google 도메인은 인위적인 가짜 Chrome UA 주입을 배제하고 순정 엔진 지문으로 통신합니다.

### ③ 디자인 시스템 & 머티리얼 런타임

- **화면 크기 대응**: v2 크기 토큰은 1368×912 기준 화면에서 정의되고 `--nv-scale` = 보기 모드 배율(1 / 1.25) × 창 높이÷912(0.82–1.6로 제한)를 곱합니다. `NvRoot`가 창 크기 변경 시 `--nv-vscale`을 갱신합니다. 창이 커져도 구성 비율이 유지됩니다.

- **0–100 머티리얼 강도**: `<html>`의 `--material-intensity`(0–1)로 제어되며, 기본값은 `0`(완전 불투명). 저사양 환경에서 불필요한 GPU 오버헤드를 막기 위해 기본 상태에서는 `backdrop-filter` 속성을 전혀 렌더링하지 않습니다.
- **모션 시스템**: 모든 상호작용은 6개 레시피(`press`, `lift`, `reveal`, `emerge`, `enter`, `pulse`)와 `transform: translateZ(0)` 하드웨어 레이어 승격으로 60fps 무지연 반응을 보장합니다.
- **대시보드 스크롤 안내**: 상단·하단 그라데이션은 현재 대시보드 스크롤 위치가 실제로 더 이동할 수 있을 때만 표시합니다. 갤러리·파인더·스트리밍 화면에서 홈으로 돌아오면 새 스크롤 영역에 감시를 다시 연결하고 첫 화면 상태를 다시 계산합니다.
- **v2 디자인 시스템**: `.nv-root` 범위의 v2 토큰(`src/app/styles/v2/`)과 `Nv*` 컴포넌트(`src/shared/ui/v2/`). 명세는 `DESIGN.md`, 제품 사실은 `PRODUCT.md`, 살아 있는 가이드는 DEV 브라우저 `/styleguide`.

### ④ 초경량 미디어 갤러리 및 비디오 플레이어 (`GalleryPage`, `widgets/gallery-v2`, `PhotoViewer`, `InAppVideoModal`)

> 갤러리 v2 개편 완료(P1–P7). 태블릿형은 Google 포토 방식(타임라인 + 폴더 탭), TV형은 "모아보기" 선반 홈입니다. 실제 파일 시스템·재생(mpv) 동작은 `pnpm tauri dev`와 Surface 실기에서 확인이 필요합니다.

1. **갤러리 v2 화면 (`GalleryV2`, `GalleryHeader`, `JustifiedGrid`)**:
   - 상단 바 하나: 위치 이름이 제목(누르면 위치 메뉴), 개수 줄(사진 N · 동영상 N, 2만 개 초과 시 "처음 N개만 표시"), 가운데 "사진 | 폴더 | 동영상" 탭, 오른쪽 검색(펼침형)과 정렬 메뉴(날짜·이름·크기 + 최신순/오래된순·가나다순/역순·큰/작은 파일부터).
   - **사진** 탭: 고른 위치의 하위 폴더 전체 사진+동영상(재귀 스캔, 기본 최신순). **동영상** 탭: 같은 위치의 동영상만. **폴더** 탭: 경로(브레드크럼) + 하위 폴더를 앨범 카드(4:3 표지 = 폴더 안 가장 최근 사진, 이름, "N개 · 하위 폴더 있음")로 보여 주고, 그 아래 그 폴더의 사진·동영상. 표지·개수는 `get_folder_summaries`로 48개씩 받아 최대 600개까지 캐시합니다(`useFolderSummaries`). 상단 개수 줄은 폴더 수도 함께 표시합니다. 정렬은 탭마다 따로 저장(`novus.gallery.v2`: 위치·탭·폴더·정렬).
   - 타일은 원본 비율 정렬(justified, `shared/lib/justifiedLayout.ts`): 줄 높이 `--gv-row`(176px × 배율), 간격 `--gv-gap`. 줄마다 폭을 꽉 채우고 마지막 줄은 왼쪽 정렬. 크기를 모르는 항목은 1.4 비율로 추정해 두었다가 페이지가 오면 다시 배치합니다.
   - **타임라인(P3)**: 날짜순일 때 사진·동영상 탭은 `get_media_timeline`의 월 묶음마다 제목("2026년 11월" + 개수)을 달고 그 아래에 정렬 그리드를 둡니다. 이름·크기순은 묶음 없이 한 덩어리입니다.
   - **날짜 스크러버(`DateScrubber`)**: 오른쪽 여백의 얇은 손잡이. 스크롤하면 나타나고 1.4초 뒤 사라집니다. 끌거나 트랙을 누르면 그 위치로 이동하고, 말풍선에 읽는 선(화면 위 25%)의 달을, 트랙에 연도 표시를 보여 줍니다. 스크롤이 화면 3배 미만이면 숨깁니다.
   - **밀도**: 두 손가락 핀치나 ctrl+휠(트랙패드 핀치)로 줄 높이를 0.66 / 1 / 1.5배 3단계로 바꾸고 `novus.gallery.v2.density`에 저장합니다.
   - **스크롤 기준점**: 추정 줄이 실제 크기로 바뀌거나 밀도가 바뀌어도 화면 맨 위 첫 줄의 사진을 기준으로 `scrollTop`을 보정해 읽던 자리가 튀지 않습니다(브라우저 자체 `overflow-anchor`는 끔).
   - 가상화: 화면 위아래 반 화면 높이 안의 줄만 DOM에 두고(마운트 창은 줄 인덱스가 바뀔 때만 갱신, 그리드 위치는 크기·배치가 바뀔 때만 측정), 실패한 페이지는 1·2·4초 간격으로 세 번까지 다시 요청합니다. 스크러버 손잡이는 ref로 transform만 바꾸고 달이 바뀔 때만 다시 그립니다. 본문은 `touch-action: pan-y`라 두 손가락 핀치가 웹뷰 확대 대신 밀도 변경으로 갑니다.
   - 보이는 범위 + 120개를 `ensureRange`로 요청합니다(1368×912 기준 타일 약 50개, 전체 DOM 약 230개).
   - 데이터: `features/browse-media`의 `useGallery`(상태)와 `useMediaCollection`(희소 페이지 컬렉션: 스냅샷 인덱스 기준 배열에 80개 페이지를 필요한 곳부터 채움, 동시 2개). 라이브러리(`slot: "library"`)와 폴더(`slot: "folder"`) 스냅샷이 따로 살아 있어 탭을 오가도 다시 스캔하지 않습니다.
   - **TV형(P5, `GalleryShelves`)**: TV 자세에서만 첫 탭 "모아보기"가 생기고 기본으로 열립니다. 최근 사진·동영상·폴더(표지 카드) 가로 선반을 방향키로 이동하고(포커스 시 1.06배 + 잉크 링, 줄이 따라 스크롤), 선반마다 "모두 보기 ›"로 사진·동영상·폴더 탭에 들어갑니다. 선반당 최대 18개, 동영상 선반은 별도 슬롯(`videos`)이지만 같은 위치의 재귀 걷기 캐시를 재사용합니다. 태블릿 자세로 바꾸면 "모아보기"는 사라지고 사진 탭으로 엽니다.
   - 갤러리는 이제 공간 탐색(방향키 포커스)이 켜져 있습니다. 이미지 뷰어는 키를 캡처 단계에서 먼저 받아 `preventDefault`하므로 뷰어가 열린 동안 뒤쪽 그리드의 포커스는 움직이지 않습니다(동영상 모달은 원래 캡처 단계).
   - 독 뒤로가기: 뷰어 → 동영상 → 폴더 탭 이력 → 홈 순서.
   - 브라우저 개발용 샘플: `pnpm dev`에서 `localStorage.setItem("novus.dev.mediaFixture","1")` 후 새로고침하면 파일 시스템 없이 샘플 640개로 갤러리를 확인할 수 있습니다(동적 import, 프로덕션 빌드에 포함되지 않음).
2. **영속 썸네일 캐시 엔진 (`src-tauri/src/commands/thumbnail.rs`)**:
   - Rust 블로킹 작업 풀에서 원본을 EXIF 방향대로 돌려 축소해 JPEG Base64 URI를 만듭니다. 격자는 320px, 뷰어는 디코딩을 마친 1600px 기본 이미지·확대 시 3200px를 사용합니다. 현재 원본을 한 번 전체 디코딩하므로 매우 큰 원본의 순간 메모리 사용은 별도 성능 측정이 필요합니다.
   - 캐시 키에 파일 경로·크기·수정 시각·출력 크기를 반영합니다. 앱 캐시 디렉터리에 재시작 후에도 유지하고 256MB를 넘으면 오래된 항목부터 정리합니다. 프런트엔드는 요청을 최대 2개 동시에 처리하며 같은 요청을 합치고, 대기 중 화면을 벗어난 타일 요청을 취소합니다.
3. **갤러리 목록 스냅샷·정렬 (`media_fs.rs`)**:
   - Rust가 스냅샷을 슬롯별(`library`, `folder`)로 하나씩 유지하고 80개씩 전달합니다. 검색은 250ms 입력 대기 후 새 스냅샷을 만들며 날짜·크기·파일명 정렬을 지원합니다.
   - 재귀 스캔(사진·동영상 탭)은 숨김·심볼릭 링크·시스템 폴더를 건너뛰고 최대 20,000개·8단계까지 걷습니다. 걸은 결과는 2분 동안 캐시되어 탭·정렬 전환은 메모리에서 다시 거릅니다(새로고침은 다시 걷기).
   - 페이지마다 사진 헤더만 읽어 가로·세로(EXIF 방향 반영)를 채웁니다. `get_media_timeline`은 월별 묶음을 돌려줍니다(P3 날짜 스크러버용).
4. **사진 뷰어 (`widgets/gallery-v2/ui/PhotoViewer.tsx`, `photo-viewer.css`)**:
   - Apple 사진·Google 포토 방식. 테마와 무관하게 검은 무대 위 사진 한 장, 위·아래는 사진 스크림(그라데이션) 위에 크롬을 둡니다.
   - 위: 뒤로(원) · 파일명 · "날짜 · 시각 · N / 전체" · 정보(원, 누르면 오른쪽에 날짜·해상도·파일 크기·형식·폴더 패널) · 닫기(원).
   - 아래: 필름스트립(현재 기준 앞뒤 7장, 누르면 이동) 위에 조작 줄: 이전/다음(원), 축소·배율·확대, 맞춤/채우기, 자동 재생 + 간격(10/15/30초 세그먼트).
   - 가운데 탭은 크롬 숨김/표시, 좌우 25% 탭은 이전/다음. 스와이프, 핀치·휠·더블탭 확대(1.5배 이상이면 3200px 요청). 자동 재생 중에는 3초 동안 입력이 없으면 크롬이 숨습니다.
   - 사진 전환은 크로스페이드: 다음 사진을 디코딩하는 동안 이전 사진을 그대로 두고, 새 사진이 220ms에 걸쳐 나타나면 뒤 사진을 치웁니다(로딩 스피너 깜빡임 없음).
   - 뷰어 목록은 컬렉션에서 연 사진이 속한 "연속으로 불러온 구간"입니다. 구간 시작은 열 때 고정되고 끝으로만 늘어납니다(인덱스가 흔들리지 않음). 스크러버로 중간에 점프한 뒤 열면 위치 표시("N / 전체")는 숨깁니다.
   - 리모컨·키보드: 열면 포커스가 뷰어로 들어가고(Tab은 뷰어 안에서만 순환) 닫으면 연 타일로 돌아갑니다. 사진 위에서는 ←/→가 사진 이동, ↓/↑는 필름스트립·조작 줄로 포커스 이동, 조작 위에서는 화살표가 조작 사이를 움직이고 Esc는 언제나 닫기. 자동 재생 중 크롬이 숨으면 포커스는 무대로 옮기고, 아무 키나 마우스 움직임으로 크롬이 다시 나타납니다.
   - 이동·핀치 확대 중에는 transform을 이미지에 직접 써서(rAF) 크롬이 다시 그려지지 않고, 손을 떼면 상태에 반영합니다. 동작 줄이기에서도 전환 애니메이션을 0.01ms로 두어 이전 사진이 남지 않습니다.
5. **인앱 우선 비디오 재생 (`InAppVideoModal` & `play_video_native`)**:
   - v2 외형(`widgets/gallery/ui/video-v2.css`): 사진 뷰어와 같은 검은 무대, 위·아래 스크림, 원형 뒤로·흰 원 재생 버튼, 흰색 타임라인. 구조와 네이티브 호스트/오버레이 창의 투명 규칙은 그대로입니다. 브라우저 개발 서버에서는 `convertFileSrc`가 경로를 그대로 돌려줘 화면이 깨지지 않습니다(재생은 Tauri에서만).
   - `libmpv`가 준비된 OS에서는 갤러리 영상이 네이티브 표면에서 하드웨어 가속(D3D11 / Metal)으로 재생됩니다. 바이너리가 없으면 WebView2/WebKit `<video>`로 자동 폴백하며, 이 경로의 로컬 미디어 로딩을 위해 Tauri asset protocol이 활성화되어 있습니다.
   - **의존성 자동 관리 (`pnpm setup:mpv`)**: `scripts/setup_mpv.py`를 통해 Windows 및 macOS용 검증된 `libmpv` 바이너리를 `src-tauri/bin/mpv/`에 자동으로 다운로드·추출·스테이징합니다. 바이너리 파일은 대용량 및 라이선스 분리를 위해 `.gitignore` 처리되어 소스 저장소 용량을 낭비하지 않습니다.
   - **Tauri 번들링 연동**: `tauri.conf.json`의 `bundle.resources` 및 `macOS.files`에 `bin/mpv`가 등록되어 있어 프로덕션 인스톨러 빌드 시 배포 패키지(`Resources/mpv`, `Frameworks/mpv`)에 자동 포함됩니다.
   - **Windows (`embedded_player.rs`)**: 64비트 메인 윈도우 HWND의 자식 Win32 윈도우(`STATIC` 창)를 생성하고 `wid`로 바인딩하여 D3D11 GPU 가속으로 렌더링합니다. 64비트 포인터 무결성을 위해 `surface as usize`로 전달됩니다.
   - **macOS (`macos_player.rs` + `macos_video_view.m`)**: `WKWebView` 아래에 `NSView`를 서브뷰로 추가하고 Metal/OpenGL GPU 가속으로 렌더링합니다. 개발 모드 및 번들 배포 환경 모두에서 `bin/mpv` 서브디렉토리를 정상 인식합니다.
   - **미디어 플레이어 컨트롤 바 (`VideoPlayerControls`)**:
     - 타임라인 탐색 바(인터랙티브 스크러빙), 재생/일시정지 토글, 10초 앞뒤 이동, 정밀 음량 조절 및 음소거, 디지털 시간 표시(현재/전체), 전체화면 토글을 제공합니다.
     - 네이티브/웹뷰 모두 화면 클릭·터치로 상·하단 조작 바를 토글하고 3초 무조작 후 숨깁니다. 버튼·슬라이더 조작 중에는 숨김을 보류합니다.
     - 키보드 단축키(Space: 재생/정지, 좌우: 10초 이동, 상하: 볼륨, M: 음소거, F: 전체화면)를 지원합니다.
     - Rust 백엔드 `get_embedded_video_state`를 10초 주기로 폴링하여 MPV C API(`mpv_get_property_string`)의 실제 시간·길이·재생 상태와 완벽히 동기화됩니다.
   - 재생 실패 시 사용자가 외부 재생을 선택할 수 있습니다. 설치된 MPV 실행 파일이 있으면 우선 사용하고, 없으면 OS 기본 플레이어로 폴백합니다.
6. **대량 목록 DOM 상한**:
   - 갤러리와 파일 모두 보이는 줄만 마운트하는 가상화를 씁니다.
7. **탐색 연속성 및 화면 상태**:
   - 파인더는 현재 폴더와 최근 50개 방문 경로를 `localStorage`에 저장해 재시작 후에도 복원합니다. 갤러리는 위치·탭·폴더·정렬을 `novus.gallery.v2`에 저장합니다.
   - 파인더는 폴더/파일 수, 이름·날짜·크기 정렬, 검색 결과와 접근 오류를 표시하고, 이력이 없을 때 뒤로가기로 홈으로 돌아갑니다.

### ⑤ 서브페이지 표준 시스템 독 (`SubpageDock`) & 파일 (`FinderPage`, `widgets/files-v2`)

1. **서브페이지 공통 독 규약 (`SubpageDock`)**:
   - 대시보드를 벗어난 모든 내부 화면(갤러리, 파인더 등)은 화면 한쪽에 일관된 시스템 독을 고정 렌더링합니다.
   - 홈, 방문 기록 기반 뒤로가기, 현재 시각, 새로고침, 툴 액션 슬롯을 표준화했습니다. 뒤로가기는 더 이상 상위 디렉터리 이동을 겸하지 않습니다.
   - 스트리밍용 `InAppDock`도 동일한 `SubpageDock`을 조합하므로 홈·뒤로·새로고침 UI와 아이콘 모션이 한 구현에서 관리됩니다.
   - 좌우 독의 화면 제목은 회전하지 않고 가로 두 줄로 표시하여 한글을 정상 방향으로 읽을 수 있습니다.
2. **파일 (`FilesV2`, `files-v2.css`)** — iPadOS 파일·Windows 11 태블릿 탐색기 방식, 갤러리와 같은 문법:
   - 왼쪽 사이드바: "즐겨찾기"(홈·바탕화면·문서·다운로드·사진·동영상, 이름은 UI 언어로 표시: `shared/lib/locationLabel.ts`)와 "드라이브". 현재 폴더가 속한 가장 깊은 위치를 표시합니다.
   - 위: 상위 폴더(↑), 폴더 이름(제목 크기) + "폴더 N개 · 파일 N개", 오른쪽에 펼침형 검색, 정렬 메뉴(`NvMenu`, 갤러리와 같은 순서 문구), 목록 | 아이콘 세그먼트(`novus.files.v2.layout`에 저장). 그 아래 경로(브레드크럼).
   - 목록: 아이콘 칸(사진은 썸네일) · 이름 · 유형 · 크기 · 수정일 · 폴더 화살표. 창 폭 1100px 이하에서는 유형·수정일 열을 접습니다. 아이콘 보기: 4:3 카드(사진은 썸네일, 그 외는 형식 아이콘 + 확장자), 이름, 크기.
   - 페이지 버튼 대신 가상화: 화면 위아래 반 화면 높이 안의 줄만 DOM에 둡니다(217개 폴더 기준 약 30개, DOM 약 310개).
   - 열기: 사진은 Novus 사진 뷰어(그 폴더의 사진을 넘겨 봄), 동영상은 Novus 플레이어, 그 밖의 파일은 OS가 정한 앱. 실패하면 "“이름”을(를) 열 수 없어요…" 같은 평이한 안내를 4초간 보여 주고 원인은 콘솔에만 남깁니다.
   - 리모컨: 처음 방향키를 누르면 첫 파일로 들어가고, 사이드바·헤더·목록 사이를 방향키로 오갈 수 있습니다(독·사이드바·목록은 포커스를 가두지 않음).

### ⑥ 공통 아이콘 모션 시스템 (`MotionIcon`)

### 내장 플레이어 조작 UI 복구

- 상·하단 조작 UI는 3초 무조작 후 숨고 화면 클릭·터치로 다시 표시하거나 즉시 숨길 수 있습니다. 영상 클릭은 재생/일시정지 대신 UI 토글로 동작합니다. 네이티브 Windows HWND 입력과 macOS 클릭 제스처는 embedded-video-input 이벤트로 전달되고 세션 ID로 필터링됩니다. Windows 네이티브/웹뷰 영상의 표시 영역은 고정하고 조작 UI만 140ms 페이드로 전환합니다.
- 버튼/타임라인 포커스 상태의 Escape도 처리하며, 창 전체화면이면 먼저 해제하고 다음 입력에서 갤러리로 복귀합니다. 종료 버튼용 Tauri 창 닫기 권한을 명시했습니다.
- Windows 영상 크기 변경은 비동기 Win32 메시지로 처리합니다. 정리 스레드가 디코더 종료 후 HWND를 파괴하며, 종료 IPC의 대기는 최대 2초입니다. 지연 정리는 계속 수행되며 오류는 콘솔에 기록됩니다.
- Rust 회귀 테스트는 디코더 지연 시 종료 호출의 시간 제한, 종료 후 지연 정리, 작업 스레드 panic 시에도 표면 정리를 확인합니다.
- Windows 실제 UI 검증: 생성한 40초 H.264/AAC MP4를 MPV로 재생해 3초 무조작 후 자동 숨김, 영상 클릭으로 UI 복구, 재숨김, 숨김 상태의 Escape 복귀, 일시정지, 버튼 포커스 상태의 Escape 복귀, 갤러리 버튼 복귀, 반복 재열기, 재생 중 Novus 종료 후 창·프로세스 제거를 확인했습니다. Surface Pro 4의 특정 코덱·드라이버 환경은 별도 검증 대상입니다.

- 물리 터치와 macOS 입력 제스처는 코드에 연결했으며 이 Windows 환경에서는 직접 동작 검증하지 않았습니다.

### 고정 화면 위 플로팅 UI와 사진 로딩

- Windows 내장 MPV는 창 전체에 비율을 유지해 재생하고, 투명 소유 조작 창 하나가 상·하단 조작 UI를 덮어 표시합니다. 3초 숨김이나 클릭 복구로 영상 크기가 바뀌지 않습니다. 영상 복귀·종료 시 조작 웹뷰도 제거합니다. 외부 패키지는 추가하지 않았습니다.
- 사진 전환은 1600px URI의 디코딩 완료까지 중앙 로딩 바를 표시하고 전체 화면 고정 박스에 contain 방식으로 맞춥니다. 작은 미리보기 확대와 전환 중 수평 이동을 제거했으며, 확대·이동·채우기 선택은 유지합니다. 로딩 실패 시 재시도할 수 있습니다.

- 최종 Windows UI 검증에서 MPV 영상 위 반투명 플로팅 바 표시와 자동 숨김 전후의 동일한 영상 영역, Escape 복귀 시 영상·조작 창 동시 정리, 가로·세로 PNG 로딩 바와 contain 맞춤을 확인했습니다. 테스트 파일은 검증 후 제거했습니다.

### 창 모드 및 스트리밍 전체화면

- 대시보드 전체화면 버튼과 F11은 메인 창의 공통 모드를 전환합니다. 버튼 설명과 접근성 상태는 현재 모드를 반영하며 전환 실패 시 닫을 수 있는 안내를 표시합니다. 브라우저 개발 환경에서는 DOM Fullscreen API로 전환합니다.
- Windows 서비스 플레이어 전체화면은 WebView2 네이티브 이벤트로 감지합니다. 독을 제거하고 웹뷰를 창 전체로 확장하며 해제 후 독과 이전 Novus 창 모드를 복원합니다. Novus가 이미 전체화면이었다면 플레이어만 해제해도 Novus 전체화면은 유지됩니다.
- 홈·앱 교체·페이지 새로고침·탭 닫기는 임시 전체화면 상태를 정리합니다. 웹뷰 세대와 revision을 검사해 백그라운드/폐기된 페이지 이벤트와 이전 레이아웃 요청이 현재 화면을 덮지 않게 합니다.
- 서비스 전체화면 컨테이너에는 상단 입력으로 다시 표시할 수 있는 보조 종료 버튼을 제공합니다. 3초 후 숨기며 영상 영역 크기는 바꾸지 않습니다. 실제 video/iframe 요소 전체화면에서는 서비스/브라우저 기본 조작을 유지합니다.
- 내장 영상의 전체화면 버튼/F도 공통 메인 창 상태를 사용하고 조작 창에 현재 모드를 동기화합니다. 전체화면에서 Escape는 먼저 창 모드를 복귀시킵니다. 다음 Escape에서 영상을 닫습니다.
- macOS의 서비스 전체화면 독 연동과 Surface Pro 4의 물리 터치·배율·다중 모니터 검증은 별도 작업입니다. Netflix 유료 콘텐츠 재생은 인증·DRM 환경을 갖춘 상태에서 검증해야 합니다.
- 공통 독의 전환 버튼으로 키보드 없이 창 모드를 바꿀 수 있습니다. Escape는 토글 대신 명시적 전체화면 해제를 요청하며 내장 영상 조작 창은 전환 후 키보드 포커스를 복원합니다.
- Windows 실제 앱 검증: 대시보드/F11/공통 독의 모드 전환, 최대화 상태 복원, YouTube 전체화면 진입 시 독 제거와 해제 후 복원, Novus 전체화면 유지, 보조 종료 버튼의 자동 숨김 및 상단 입력을 통한 해제, Alt+왼쪽의 전체화면 해제 우선 처리와 다음 입력의 페이지 탐색을 확인했습니다.
- 최종 내장 MPV 검증: 창 모드에서 재생 후 F로 전체화면 진입, 첫 Escape에서 영상 유지·창 모드 복원, 두 번째 Escape에서 영상/조작 창 정리·갤러리 복귀를 확인했습니다. 테스트에 사용한 임시 영상은 검증 후 제거합니다.

### 배포 기반 및 자동 빌드

- 준비 버전은 0.2.0이며 정식 Release 게시는 별도입니다. 일반 사용자 배포 형식은 Windows x64 NSIS EXE 하나로 통일했습니다. 기존 EXE의 currentUser 설치·제품명 novus·식별자 com.novus.hub를 유지합니다.
- `pnpm release:version <버전>`으로 버전을 동기화하고 `pnpm release:check [--tag v<버전>]`으로 검사합니다. `release:test`는 잘못된 버전·태그·설치 계약 변경을 검증하며 `release:info`는 현재 체크아웃 추적 정보를 출력합니다. 자세한 절차는 RELEASING.md를 따릅니다.
- 공개 저장소 HYS1753/novus를 소스와 배포 대상으로 사용합니다. 실제 기존 MSI 설치본이 있는지는 미확인으로, MSI에서 EXE로의 자동 이전을 보장하지 않습니다. 실제 설치·설정 보존 검증은 배포 전 검증 단계에서 수행합니다.
- 2단계는 암호화된 업데이트 키와 Windows EXE·서명·`latest.json` 구성을 제공합니다. `pnpm release:keygen`은 사용자 터미널에서 키를 생성하고 검증 파일에 서명하며, 이미 있는 키는 재생성하지 않습니다. 공개 키만 저장소에 복사합니다. `pnpm release:signing check` 및 `verify <파일>`로 구성과 서명을 검증하고 `manifest <설치파일>`로 메타데이터와 SHA256SUMS를 만듭니다.
- `release:test`는 실제 Tauri CLI의 임시 키·서명으로 변조 파일, 잘못된 공개 키, 변조된 trusted comment, 버전·파일명 불일치를 거부하는지 확인합니다. 테스트 키는 생산용 키와 분리하며 종료 후 삭제합니다.
- 3단계 `Windows signed release` 워크플로는 v* 태그를 검사한 뒤 서명된 Windows x64 설치 파일과 Release 초안을 만듭니다. 수동 실행은 main에서 서명 빌드·산출물 검증만 수행합니다. 기존 Release 버전은 덮어쓰지 않으며 공개 게시는 설치·updater 검증 후 별도로 진행합니다. Repository secrets 2개와 실행 방법은 RELEASING.md를 따릅니다.
- `release:ci guard/prepare/verify`는 main 포함 여부, 소스 커밋·Git tree·워크플로 실행 번호, 고정 MPV 해시와 산출물 목록·해시·서명을 검사합니다. 원래 실행과 다른 시도 번호의 산출물, 변조된 manifest와 예기치 않은 파일은 차단합니다.
- Windows MPV 다운로드는 `scripts/mpv-windows.json`의 존재하는 고정 URL과 압축본/DLL SHA256을 사용합니다. 기존 로컬 DLL도 해시가 다르면 다시 준비합니다. 로컬에 DLL이 없거나 내려받기에 실패하면 CI가 중단됩니다. macOS 준비 방식은 기존과 같습니다.
- Windows updater 런타임은 main 전용 IPC, 타입 안전한 shared 래퍼, 상태 이벤트, 취소·중복 요청 제어, HTTPS/버전 제한, 임시 파일 스트리밍과 서명 검증, NSIS 설치 시작 경로를 제공합니다. 상세 계약과 실제 설치 검증의 남은 범위는 UPDATE_RUNTIME.md를 따릅니다.
- Tauri updater 2.14.1의 요구사항으로 코어 2.12.5·WebView2 0.39.1·JS API/CLI 2.12.4를 사용합니다. Windows 라이브러리 단위 테스트에도 Common Controls v6 매니페스트를 링크해야 합니다. CI는 Rust updater/기존 회귀 테스트도 실행합니다.
- 네이티브 updater 테스트는 임시 Tauri 서명과 루프백 서버·MockRuntime IPC로 동작합니다. 생산 개인 키나 Secret을 사용하지 않고 설치 프로그램을 실행하지 않습니다. 실제 설치·재시작·사용자 데이터 보존은 정식 설치본과 더 높은 서명 버전을 준비한 통합 검증 대상입니다.
- 설정 시트 맨 위 `UpdateSettings`는 자동 업데이트 ON/OFF, 수동 확인·다운로드·취소, 진행률, 릴리즈 내용, 오류·재연결, 명시적 설치 확인을 제공합니다. 기본 ON은 `<app_config_dir>/updater.json`에 저장하고 실패는 OFF로 처리합니다. 자동 작업은 설치본에서만 시작 30초 뒤·6시간 간격으로 조회·다운로드합니다. OFF는 자동 작업만 취소하며 수동 작업과 ready 파일은 유지합니다. 설치·재시작은 항상 사용자 확인이 필요합니다.
- `features/update-app/model/controller.ts`는 단일 외부 스토어로 revision·중복 명령·설치 확인 버전을 보호합니다. 설정 닫기와 무관하게 작업을 유지하고 대시보드에만 새 버전/준비 알림을 표시합니다. 스트리밍 중 설정 열기에서는 자식 웹뷰를 순차적으로 숨기고 복원합니다. `pnpm update:test`의 가짜 시계·API 테스트와 네이티브 설정/자동 취소 테스트를 CI에서도 실행합니다.
- 6단계 실제 설치·재시작·데이터 보존 및 정식 배포 검증은 사용자 시작 지시 후 진행합니다. 현재 공개 Release와 새 버전 태그는 생성하지 않습니다.
