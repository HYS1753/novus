# Novus Low-Spec Performance Guide

> **타깃 기기 프로필**: Microsoft Surface Pro 4 (Intel Core m3-6Y30 듀얼코어, Intel HD 515, **4GB LPDDR3 RAM**, 12.3인치 2736x1824 고해상도 터치 디스플레이)

---

## 1. 저사양 디바이스 성능 도전 과제

1. **극히 제한된 RAM (4GB)**: Windows 10/11 OS 자체 점유율만 2~2.5GB에 달하므로, 앱 단독 메모리 사용량을 **30~50MB** 이내로 엄격히 통제해야 합니다.
2. **저전력 듀얼코어 CPU (4.5W TDP)**: 잦은 JavaScript 가비지 컬렉션(GC)이나 반복적인 DOM 리플로우가 발생하면 즉시 프레임 드랍(Jank)이 발생합니다.
3. **고해상도 디스플레이 (2736x1824)**: 픽셀 수가 많아 무거운 CSS 필터(blur, 복잡한 box-shadow 등)를 남발하면 내장 그래픽(HD 515)에 과부하가 걸립니다.

---

## 2. 프론트엔드 최적화 5대 원칙

### ① 무거운 CSS 필터 금지 및 GPU 하드웨어 가속 강제

- `backdrop-filter`와 `filter: blur(...)`는 구형 인텔 내장 GPU에서 치명적인 렌더링 지연을 유발합니다. **앱 어디에서도 쓰지 않습니다.** 예전 머티리얼(프로스팅) 경로(`html[data-frost]`, `--material-blur-*`)는 삭제했고, 설정의 "사진 위 글자 배경" 슬라이더(`--material-intensity`)는 이제 사진 스크림 세기만 바꿉니다. 빛 번짐(스트리밍 로딩·온보딩 미리보기)은 서비스 색의 radial-gradient를 opacity·scale로만 움직여 표현합니다.
- 움직이는 요소에 `filter`(drop-shadow 포함)를 걸지 않습니다. 정적인 요소의 drop-shadow 한 번(띠의 novus 로고)만 허용합니다.
- **무한 반복 애니메이션은 화면이 바쁠 때만**: 로딩 표시(스켈레톤, 스피너, 스트리밍 로딩)처럼 끝나면 사라지는 것만 무한 반복합니다. 항상 켜진 홈의 안내 꺽쇠는 3번 움직이고 멈추며 앰비언트에서는 돌지 않습니다. 홈·갤러리·파일을 가만히 두면 실행 중인 애니메이션이 0개여야 합니다(`document.getAnimations()`로 확인).
- `will-change`는 실제로 계속 움직이는 큰 요소(홈 사진 접힘, 사진 뷰어의 사진, 스크러버 손잡이)에만 둡니다. 아이콘마다 상시 레이어를 만들지 않습니다.
- 프로스팅을 켜는 경우 동시에 화면에 존재하는 블러 레이어 수를 8개 미만으로 유지하고, 블러값 자체를 애니메이션하지 않습니다.

### ①-1 모션은 transform / opacity 로만

- 모든 인터랙션은 6개 모션 레시피(`press` · `lift` · `reveal` · `emerge` · `enter` · `pulse`) 중 하나로만 표현하며, 컴포넌트는 duration을 직접 선언하지 않습니다.
- 레이아웃 속성(`width`, `height`, `top`, `margin`)과 컬러 램프, 블러 반경은 애니메이션 대상이 아닙니다. 리플로우/리페인트 비용이 프레임 예산을 넘깁니다.
- 반복 모션(스켈레톤 시머, 무한 진행바)은 화면당 필요한 최소 개수만 두고, `prefers-reduced-motion: reduce`에서는 전역 규칙으로 완전히 정지합니다.
- 모션/트랜지션이 있는 모든 인터랙티브 요소(버튼, 카드)에는 반드시 `transform: translateZ(0)`를 부여하여 독립 컴포지팅 레이어로 승격시킵니다.
- 위치 이동이나 크기 조절은 `top`, `left`, `width`, `height` 대신 항상 **`transform: translate(...)` 및 `scale(...)`**만을 사용합니다.

### ② 저빈도(Low-frequency) 타이머 및 백그라운드 절전

- 시계/날짜 위젯은 1초 단위(`1000ms`)가 아닌 **10초 또는 30초 단위**로만 인터벌을 실행합니다 (`src/shared/hooks/useCurrentTime.ts` 참조).
- 창이 최소화되거나 비활성화되면 백그라운드 애니메이션 및 폴링을 즉시 일시정지합니다.

### ③ DOM 노드 수의 최소화 및 가상화(Virtualization)

- 렌더링 트리에 존재하는 총 DOM 노드 수를 500개 미만으로 억제합니다.
- 긴 앱 목록이나 동영상 리스트를 표시할 때는 전체를 렌더링하지 않고 화면에 보이는 요소만 렌더링하는 가상 스크롤(Virtual Shelf) 방식을 적용합니다.

### ④ 44px 이상의 터치 타겟과 즉각적인 Active 피드백

- 윈도우/태블릿 환경에서 손가락 터치 시 빗나가지 않도록 모든 터치 버튼 및 카드는 **최소 48x48px** 이상의 터치 영역을 보장합니다 (`--touch-target-min`).
- 터치 시 지연감(300ms delay)을 방지하기 위해 `-webkit-tap-highlight-color: transparent`를 전역 적용하고, `:active` 상태에서 즉각적인 `scale(0.96)` 반응을 제공합니다.

### ⑤ 가벼운 번들 사이즈 유지 (Zero Bloatware)

- Moment.js, Lodash, 대형 UI 라이브러리(Material UI, Ant Design) 도입을 엄격히 금지합니다.
- 유틸리티는 순수 JS 및 `src/shared/lib/`의 경량 함수를 사용하고, UI는 자체 제작한 순수 CSS 기반 `src/shared/ui/` 컴포넌트를 사용합니다.

### ⑥ 대용량 미디어 렌더링 및 디코딩 메모리 방어 원칙

- **원본 이미지 DOM 마운트 금지**: 사진 원본을 직접 `<img src>`로 넣지 않습니다. 격자에는 320px 썸네일, 뷰어에는 디코딩 완료된 1600px 이미지를 쓰며 확대 시에만 3200px를 요청합니다. 다만 Rust `image::open`의 원본 전체 디코딩으로 생기는 순간 메모리는 아직 측정 대상입니다.
- **현재 이미지 1장 유지**: 사진 뷰어(`PhotoViewer`)는 현재 사진 한 장(전환 중 220ms 동안만 이전 사진 포함 2장)과 필름스트립 썸네일 최대 15개만 DOM에 유지합니다. 다음 사진은 제한된 요청 큐에서 미리 준비하며 프런트엔드 Base64 URI 캐시는 문자열 길이 합계 12MiB로 제한합니다. 이는 실제 JS 힙 사용량의 상한과 같지 않습니다.
- **목록 마운트 상한**: 갤러리는 가상 격자로 현재 보이는 행과 위아래 1행만 렌더링하고, 스크롤 끝에 가까워지면 Rust 스냅샷에서 80개씩 추가로 받습니다. 정확한 전체 정렬을 위한 첫 폴더 메타데이터 스캔은 여전히 필요합니다. 파인더는 40개 단위 페이지를 사용합니다. 갤러리 스크롤 이벤트는 `requestAnimationFrame`으로 묶습니다.
- **썸네일 작업·디스크 상한**: 프런트엔드 요청은 최대 2개 동시 실행하며 같은 요청을 합칩니다. 앱 캐시 디렉터리의 JPEG 캐시는 첫 생성과 이후 32회 생성마다 용량을 확인해 256MiB 초과분을 오래된 파일부터 지웁니다. 이 상한과 실제 디코딩 중 메모리 사용은 Surface Pro 4에서 확인해야 합니다.
- **탐색 복원 비용**: 갤러리와 파인더는 이미지·파일 목록을 저장하지 않습니다. `localStorage`에는 현재 경로와 최대 50개 방문 경로만 기록하고, 재진입 시 해당 폴더를 다시 스캔합니다.
- **긴 경로 표시**: 브레드크럼은 현재 폴더와 바로 위 폴더만 기본 렌더링하고 나머지는 메뉴 안에 두어 툴바 너비가 길이에 따라 늘어나지 않게 합니다.
- **대시보드 가장자리 여유**: 카드 확대가 스크롤 영역에서 잘리지 않도록 스크롤 콘텐츠 내부에 좌우 여백을 둡니다. 상하 스크롤 안내에는 GPU 블러 대신 단색 그라데이션을 사용합니다.
- **홈 복귀 시 상태 재계산**: 대시보드가 다시 마운트되면 스크롤 영역의 실제 위치를 페인트 전에 다시 읽어 상단 그라데이션이 이전 화면 상태로 남지 않게 합니다.
- **인앱 하드웨어 미디어 경로 우선**: Windows에서 DLL이 확인되거나 macOS에서 묶인 dylib가 실제로 로딩되면 네이티브 libmpv 표면을 사용합니다. 엔진이 없는 환경에서는 WebView2/WebKit의 `<video>`를 사용합니다. 재생 오류 시 사용자 선택으로 설치된 MPV 또는 OS 기본 플레이어를 열 수 있습니다.
- **Windows 네이티브 플레이어 및 미디어 컨트롤러**: `libmpv` DLL이 앱 리소스에 있는 경우에만 Win32 자식 영상 창을 지연 생성하고 `hwdec=auto-safe`로 디코딩을 시도합니다. 영상은 DOM이나 Base64 IPC를 거치지 않습니다. 미디어 컨트롤러는 GPU 부담을 주는 블러 없이 불투명 틴트로 렌더링되며, 10초 저빈도 폴링으로 시간·길이를 동기화하고 영상 표면의 클릭 이벤트를 메인 웹뷰로 전달해 3초 자동 숨김 이후에도 상·하단 조작 UI를 복구합니다.
- **macOS 네이티브 플레이어 시제품**: 유효한 dylib가 있을 때만 메인 스레드에서 NSView를 지연 생성하고 libmpv에 연결합니다. 지원 확인은 백그라운드에서 한 번만 실행합니다. 닫을 때 재생 스레드를 끝내고 NSView를 제거합니다. dylib와 의존 파일은 빌드 시 별도 스테이징하며 Git에는 저장하지 않습니다. 실제 영상 출력과 메모리 회수는 미측정입니다.
- **기기 정보 1회 수집**: 운영체제·CPU·총 RAM·모델 등 정적 기기 정보는 앱 시작 시 Rust가 한 번만 읽고 Tauri State에 보관합니다. 설정 화면은 캐시된 값을 사용하며 시스템 정보 폴링이나 고빈도 타이머를 추가하지 않습니다. GPU와 코덱별 디코더 기능은 아직 자동 탐지하지 않습니다.
- **아이콘 모션 단일 경로**: 아이콘 효과는 `iconMotion.ts`(`[data-motion]`)만 사용하며 `transform`만 변경하고 한 번 재생 후 멈춥니다. 상시 레이어(`will-change`)를 만들지 않으며 `prefers-reduced-motion`에서 중단합니다.

## 3. 메모리 누수 방지 체크리스트

로컬 동영상의 코덱별 재생 성능과 네이티브 엔진 통합 검증 절차는 [`VIDEO_PLAYER_VALIDATION.md`](VIDEO_PLAYER_VALIDATION.md)에 정의합니다. libmpv가 감지된 개발 환경에서는 네이티브 경로를 선택하지만, 실제 화면 출력과 성능 결과는 아직 측정되지 않았습니다.

- [ ] `useEffect` 내부에서 생성된 이벤트 리스너, 타이머, Tauri 이벤트 언리스너가 cleanup 함수에서 100% 해제되는가?
- [ ] 대용량 이미지 자산을 직접 번들링하지 않고, SVG 아이콘 또는 최적화된 WebP/AVIF를 사용하는가?
- [ ] 개발자 도구 Performance 탭에서 60fps가 안정적으로 유지되는가?
- [ ] 이미지 갤러리 진입 시 수백 장의 파일이 있어도 렌더러 메모리 점유율이 60MB 이하로 억제되는가?

### 실행 앱 목록 비용

- 실행 앱 목록은 웹뷰 생성·종료에 따른 이벤트로 갱신합니다. 추가 상태 폴링이나 타이머는 없습니다.
- 독은 등록된 웹 앱 수만큼 소형 아이콘과 두 버튼을 렌더링하며, 공간이 부족하면 목록 내부를 스크롤합니다. 원격 로고 요청 대신 로컬 브랜드 이미지 또는 텍스트를 사용합니다. 블러는 사용하지 않습니다.
- 닫기는 숨김과 달리 해당 웹뷰를 파괴해 재생과 페이지 메모리를 해제합니다. 공유 브라우저 프로필과 다른 앱은 유지됩니다.

### 영상 입력 및 종료 대기

- 네이티브 입력은 Windows 호스트 HWND 서브클래스/macOS 클릭 제스처의 세션별 이벤트로 전달합니다. 마우스 위치 폴링이나 고빈도 타이머를 추가하지 않습니다. 3초 자동 숨김은 단발 타이머이며 드래그 중에는 보류합니다. 숨겨진 조작 UI는 inert 처리해 보이지 않는 버튼의 포커스·클릭을 막습니다.
- 상태·조작 응답 대기 중 Windows 세션 mutex를 보유하지 않습니다. 디코더 join은 정리 스레드에서 수행하며 UI 스레드에서 대기하지 않습니다. 창 크기는 비동기로 전달합니다.
- 디코더 정리 지연 시 창은 먼저 숨기고 호출자 대기는 2초에 종료합니다. HWND와 DLL은 작업 스레드 종료 후 정리해 사용 중 자원을 파괴하지 않습니다. 이는 멈춘 디코더를 강제 종료하는 기능은 아닙니다.

### 고정 영상 영역과 이미지 디코딩

- Windows 영상 조작은 재생 동안만 투명 소유 조작 창 하나를 지연 생성합니다. 추가 디코더는 만들지 않으며 영상 닫기에서 웹뷰도 파괴합니다. 조작 UI 표시 상태는 네이티브 영상 크기에 영향을 주지 않고 opacity만 전환합니다. 추가 웹뷰의 실제 Surface 메모리·GPU 비용은 실기기 측정 대상입니다.
- 이미지의 크기는 디코딩 전후에도 전체 뷰포트 박스로 유지하며 object-fit으로 비율을 보존합니다. 320px 미리보기 요청을 제거해 디코딩과 교체를 줄이고, 기본 1600px·확대 시 3200px 제한 및 다음 한 장 사전 요청은 유지합니다.

### 전체화면 전환 비용

- 창/플레이어 전체화면 상태는 네이티브 이벤트와 최초 조회로 동기화합니다. 주기적인 전체화면 폴링과 서비스 DOM 감시용 MutationObserver는 사용하지 않습니다. WebView2 바인딩은 Tauri가 이미 사용하는 버전을 재사용하며 새 프런트엔드 패키지는 추가하지 않습니다.
- 페이지별 이벤트 큐는 기존 비동기 런타임에서 대기하며 별도 OS 스레드를 유지하지 않습니다. 전체화면 독은 마운트하지 않고 실제 자식 웹뷰 크기를 조정합니다. 창 크기 변경과 React ResizeObserver가 이전 크기를 덮지 않도록 revision을 확인합니다.
- 서비스의 보조 탈출 UI는 버튼 한 개와 단발 3초 타이머만 사용합니다. 모션은 opacity 140ms이며 blur나 영상 크기 애니메이션을 추가하지 않습니다. 전체화면 전환 시 웹뷰·플레이어를 재생성하지 않습니다.

### 배포 기반 검사 비용

- 버전·태그·설치 계약 검사는 Node 표준 라이브러리만으로 빌드 전에 실행합니다. 앱 런타임 패키지, DOM, 상태 폴링, IPC 또는 네트워크 요청을 추가하지 않습니다.
- 버전 동기화는 루트 앱 항목만 갱신하고 의존 패키지 버전과 pnpm-lock.yaml을 유지합니다. Windows 전용 번들 설정은 NSIS 하나로 제한하며 macOS/Linux의 런타임 경로는 변경하지 않습니다.
- 서명 생성·배포 manifest 생성 도구는 개발 PC의 Node/Tauri CLI에서만 실행하며 앱 번들에 포함하지 않습니다. 업데이트 런타임과 UI의 비용은 아래 규칙을 따릅니다.
- 자동 빌드는 Windows x64 NSIS 한 종류만 수행하고 태그 또는 명시적 수동 실행에서만 시작합니다. 산출물은 7일간 보관하고 재압축하지 않습니다. MPV 다운로드·압축본/DLL 해시 검사와 소스/서명 검증은 빌드 PC에서 수행합니다.

### 업데이트 런타임 비용

- Windows 한정 Rust updater/전송 의존성을 사용하며 OS native-tls를 재사용합니다. 새 프런트엔드 패키지나 별도 updater 프로세스를 상시 실행하지 않습니다. 자동 ON인 설치본만 시작 30초 뒤·6시간 간격의 단일 타이머로 확인·다운로드합니다. 오프라인 복귀는 이벤트로 처리하고 자동 설치와 고빈도 상태 폴링은 없습니다. OFF·미설치·설정 오류에서는 예약하지 않습니다.
- 설치 파일은 캐시에 스트리밍하고 실제 수신 크기를 128MiB로 제한합니다. 서명 검증·설치 직전에는 해당 파일을 일시적으로 메모리에 읽지만 blocking pool에서 처리하며 ready 상태에서 버퍼를 보관하지 않습니다. 이 작업 동안 실제 추가 RAM 비용은 설치 파일 크기에 비례하며 평상시 메모리 목표와 구분해 측정합니다.
- 진행률 이벤트는 다운로드 중 최대 250ms 간격으로만 보내며 별도 타이머를 만들지 않습니다. main에만 전송하며 네트워크 대기 중 상태 mutex를 잡지 않습니다. 취소하면 HTTP future를 폐기하고 늦은 응답은 세대 번호로 무시합니다. 캐시 파일 정리 시 사용자 미디어나 브라우저 프로필은 접근하지 않습니다.
- 설정 UI만 전체 업데이트 스냅샷을 구독합니다. 대시보드 알림은 available/ready 버전 문자열만 구독해 진행률로 앱 루트를 다시 렌더링하지 않습니다. 시트 닫기에서 구독을 해제하며 앱 루트 정리에서 네이티브 리스너·타이머·온라인/포커스 이벤트를 해제합니다. 크기 미정 진행 바는 transform 애니메이션 하나이며 reduced-motion을 지원하고 blur를 사용하지 않습니다. 설정 파일은 최대 4KiB로 제한하고 변경 때만 저장합니다.

## 4. v2 홈 · 디자인 시스템 성능 규칙

- **불투명 면만**: v2는 `backdrop-filter`를 쓰지 않습니다. 유일한 반투명은 사진 하단·상단 스크림(그라데이션 한 장)입니다. v1 스타일과 브리지는 모두 삭제되었습니다.
- **CSS 크기**: 삭제한 v1 화면(구 파인더·갤러리·경로 표시·미디어 타일 등)의 규칙을 걷어내 CSS 번들이 148KB → 120KB, 동영상 플레이어 v2 재작성과 v1 파일 삭제 후 101KB가 되었습니다. 컴포넌트를 지울 때 그 클래스 규칙도 같이 지웁니다.
- **사진 접힘은 요소 하나의 transform**: 스크롤 이벤트마다 `requestAnimationFrame` 한 번으로 사진 `<img>`의 `translate3d`만 바꿉니다. 레이아웃 속성은 건드리지 않습니다. 띠 높이(`--nvh-band`)와 프레임 높이(`--nvh-h`)는 `ResizeObserver`에서만 갱신합니다.
- **DOM 예산**: 홈 v2 전체 약 260개 노드(1368×912 측정). 오늘 화면의 달력 42칸, 서비스 7개, 탐색기 줄을 포함합니다.
- **사진 한 장만 메모리에**: 홈과 앰비언트는 1600px 썸네일 한 장만 디코딩합니다. 교체 간격은 홈 10분, 앰비언트 1분이며 60초 미만으로 내려가지 않습니다. 사진이 없으면 1–11KB SVG 번들 아트워크를 씁니다.
- **타이머 하한**: 시계 `useNow`는 10초, 날씨는 30분(캐시 재사용), 무조작 감지는 입력마다 다시 거는 단일 `setTimeout`입니다. 폴링 루프는 없습니다.
- **웹폰트 없음**: 시스템 글꼴 스택(Segoe UI Variable + 언어별 OS CJK 글꼴)만 씁니다. CJK 웹폰트(수 MB)를 번들하지 않습니다.
- **모션 하한**: 모든 v2 모션은 `--nv-dur-*` 토큰을 쓰고, `prefers-reduced-motion: reduce`이면 0.01ms로 끝납니다. 홈의 스크롤 이동도 이때는 즉시 이동합니다.
